# Audit API Sticker untuk BASEBOT

**Tanggal temuan:** 2026-11-13
**Kesimpulan singkat:** Belum ada bukti bahwa kandidat yang ditinjau menghasilkan sticker WhatsApp siap pakai (mis. WebP dengan batas/metadata sticker yang sesuai). Pilihan paling masuk akal untuk prototipe adalah API Brat `api.siputzx.my.id` karena satu respons PNG diuji live dan tidak memerlukan key menurut dokumentasi. Tetap diperlukan konversi, validasi, batas ukuran, timeout, serta fallback di BASEBOT.

## Metode dan batas bukti

Sintesis ini menggunakan data riset terstruktur yang diberikan, bukan pengujian ulang. Metode yang dilaporkan mencakup pembacaan halaman/repository/OpenAPI publik serta GET baca-saja; request POST, kredensial, dan aksi yang mengubah data tidak digunakan. Klaim operasional hanya berlaku pada saat dan lingkungan pemeriksaan. Pembedaan penting: hasil GET live membuktikan satu respons saat itu, dokumentasi membuktikan kontrak yang dinyatakan, sedangkan source repository saja tidak membuktikan host/route masih aktif.

## Saran implementasi dan kontrol keamanan

1. **Perlakukan hasil sebagai media tidak tepercaya.** Ambil hanya dari host yang dipilih secara statis; jangan menerima URL respons atau URL latar arbitrer dari pengguna untuk kemudian di-fetch oleh server BASEBOT. Untuk route yang memang menerima URL latar, gunakan allowlist host, blok alamat private/link-local/loopback, cegah redirect ke alamat terlarang, dan batasi waktu/ukuran. Hal ini mengurangi risiko SSRF; bukan klaim bahwa kandidat tertentu rentan.
2. **Batasi respons sebelum decode/konversi.** Terapkan timeout, batas byte dan dimensi, cek `Content-Type` sekaligus signature file, tolak HTML/JSON error yang tersamar sebagai gambar, dan lakukan konversi ke spesifikasi sticker WhatsApp di sisi BASEBOT. GIF/WebM memerlukan jalur animasi dan validasi tambahan. API yang ditinjau tidak membuktikan output sticker WebP WhatsApp siap kirim.
3. **Minimalkan kebocoran input/secret.** Encode query dengan library URL, jangan kirim teks sensitif, dan jangan menyimpan URL berisi API key Agatz di log. Gunakan secret store jika Agatz kelak diuji; key pada query tidak boleh masuk log/proxy.
4. **Buat fallback dan pemantauan.** Respons 200 satu kali bukan SLA. Gunakan fallback/disable switch, circuit breaker, serta uji berkala untuk status, MIME, ukuran, dan hasil konversi.

**Rekomendasi akhir:** Mulai prototipe terbatas dengan Siputzx API utama (`api.siputzx.my.id`) karena kombinasi bukti GET PNG live, jalur integrasi sederhana, dan tanpa key menurut sumber resmi. Pertimbangkan host Asepharyana `scraper.asepharyana.my.id` sebagai alternatif PNG/GIF hanya setelah keputusan eksplisit bahwa host alternate dapat dipakai. Jangan menyebut salah satu sebagai dukungan sticker WhatsApp langsung sebelum konversi dan validasi BASEBOT berhasil.

## Implementasi plugin BASEBOT

- Command baru: `.stickerapi brat <teks>` dan `.stickerapi animated <teks>` (alias `.stapi`). Siputzx menjadi penyedia utama; route statis diambil dari `api.siputzx.my.id/api/m/brat`, sedangkan parameter animasi mengikuti source route publik (`isAnimated=true`, `delay=500`). Bukti GET live yang tersedia hanya mencakup PNG statis; jalur animasi tidak dinyatakan sebagai live-verified.
- Asepharyana `scraper.asepharyana.my.id` tersedia sebagai fallback **opt-in saja** melalui `STICKER_API_ASEPHARYANA_ENABLED=true`. Ini host alternate, berbeda dari `asepharyana.cloud`; default config menonaktifkannya. Mengaktifkannya adalah pilihan operator.
- Plugin tidak menerima URL dari chat, memakai service unduhan DNS-pinned/no-redirect BASEBOT, membatasi timeout 15 detik dan media 8 MiB, memverifikasi signature PNG/GIF, serta memakai konversi FFmpeg/WebP + metadata lokal. Teks dibatasi 300 karakter dan tidak dicatat ke log.
- Tidak ada endpoint yang mengirim WhatsApp WebP sticker siap pakai; seluruh media generator dianggap input tidak tepercaya dan dikonversi di sisi bot.
